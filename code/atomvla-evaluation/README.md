# AtomVLA Evaluation

This is the executable evaluation layer for the paper. It never creates projected scores. Every success must come from an injected simulator or robot backend response. `evaluate.py` handles fixed manifests, variants, results, per-task summaries, and error accounting. `extract_features.py` consumes paired hidden states and reports a shared PCA projection plus paired distance. Environment adapters are passed with `--backend command`; the command receives a JSON request and must return measured success/evidence.

The checked-in manifests cover the paper's fixed protocols: LIBERO averages,
LIBERO-Pro subsets, three RoboTwin tasks, three RMBench tasks, and five
real-robot tasks. Each has three deterministic test seeds as a small protocol
fixture; production runs should replace the fixture rows with the released
episode IDs while keeping the same schema.

Examples:

```bash
PYTHONPATH=code/atomvla-evaluation python code/atomvla-evaluation/evaluate.py \
  --mode ablation --manifest code/atomvla-evaluation/manifests/robotwin_three_tasks.jsonl \
  --out runs/ablation --backend command \
  --command python code/atomvla-evaluation/adapters/robotwin_adapter.py
PYTHONPATH=code/atomvla-evaluation python code/atomvla-evaluation/evaluate.py \
  --mode memory --manifest code/atomvla-evaluation/manifests/rmbench_three_tasks.jsonl \
  --out runs/memory --backend command \
  --command python code/atomvla-evaluation/adapters/rmbench_adapter.py
PYTHONPATH=code/atomvla-evaluation python code/atomvla-evaluation/extract_features.py \
  --checkpoint /path/to/checkpoint --out runs/features.json
```

The same manifest and seeds must be used across variants. Failed commands are
recorded as errors and count as unsuccessful trials; they are never silently
removed. The default adapter response is `unavailable` until a real simulator
or robot adapter is configured with `ATOMVLA_ADAPTER_MODULE`. A checkpoint
feature run requires `hidden_states.npz` or a real extractor configured with
`ATOMVLA_FEATURE_EXTRACTOR`; no synthetic features are generated by this
package. Each run writes `protocol.json`, `results.json`, `results.csv`,
`summary.json`, and `manifest_check.json`.
