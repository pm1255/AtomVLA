# 新版 AtomVLA 第一阶段与实数据诊断

`stage1.py` 实现字符串程序交叉熵和每活动臂唯一终点位姿监督。复用既有 Qwen3-VL 视觉语言主干与连续 Query 实现，替换旧版8帧位姿和光流目标。**不是完整 image/action MoT 联合训练实现**。

程序分支：当前多相机图像、指令、机器人/坐标标签、当前 EEF/夹爪状态 → 自回归原子调用；只对答案 token 计算逐样本归一化交叉熵，应用清单的程序权重0.5。

Query 分支：当前输入 + 教师提供的字符串程序 → 连续 Query → 每臂一个终点 xyz+xyzw。显式使用程序条件；终点数值、关键帧、事件时间不进入输入。终点位置为米制 SmoothL1(beta=0.05)，旋转使用符号不变损失 `1-dot(q_pred,q_target)^2`，报告测地角误差。有效臂在算损失之前筛选，缺失臂不是零位姿监督。Query不预测多个中间点。

本入口教师提供字符串调用，尚未加入模型生成程序的混合训练；推理时必须改用模型生成的程序，不可使用未来真值。这里配置为全参数更新，以复用现有full_ft代码的训练约定；没有声称验证了论文冻结骨干的另一套预算。

关键帧标签已经存在且读取器可解码，但未来图像生成/变长生成掩码/MoT尚未实现；不得以RGB重建小头替代并宣称方法已完成。动作权重为0，因当前RoboTwin发布没有已验证控制目标。当前监督总式为：

`L = 0.5 * L_program + 1.0 * (L_terminal_position + L_terminal_rotation)`

`smoke.py` 是32步默认、最多100步的CPU诊断入口。使用真实预训练处理器、已转换真实轨迹，以及缩小后随机初始化的真实Qwen3-VL架构（包含视觉塔）。16条训练/8条验证轨迹，同一机器人，一条轨迹仅一个观测锚点；种子组互斥。显式随机初始化，不能代表完整预训练2B性能。

验证覆盖：未来标签输入隔离、程序改变时Query随之变化、非活动臂NaN掩码、四元数正负等价、视觉/语言/文本头/Query/位姿头梯度、真实优化步骤、固定子集前后损失、完整模型/优化器/RNG检查点及精确下一步恢复。不是GPU/多卡吞吐、闭环成功率或整套MoT验证。

运行所需PYTHONPATH包含旧实验的`code`（vendor_delta与full_ft/runtime）和新版发布读取器目录。入口参数见`smoke.py --help`。检查点复用已验证的原子保存和哈希机制，独立目录不覆盖历史实验。TensorBoard使用`semantic_stage1_smoke/`，不写入正式训练曲线。
